# EasyOJ 生产化加固设计

## 目标与边界

本设计面向学校内网、单台日用 Windows 机器上的本科作业和课堂竞赛。目标是让管理员能低成本部署，让学生能直觉地浏览题目、提交代码和查看结果，同时把评测任务限制在明确的 CPU、内存、进程、输出和文件访问边界内。系统不承诺在宿主机已被攻破、用户拥有管理员权限或 Windows 安全组件不可用时提供虚拟机级隔离；生产配置在隔离能力不可用时必须拒绝执行代码。

## 总体架构

保留 Flask 单体应用和 SQLite，评测器继续使用多进程 Worker，但改为有界并发：默认使用 `max(1, min(cpu_count - 1, 8))` 个 Worker，并允许管理员在部署向导中调低上限。每个编译和运行步骤都通过统一的 `SandboxRunner` 创建 Windows Job Object，启用进程树清理、进程数限制、CPU 时间限制和内存限制；支持时再使用 AppContainer、最小权限目录 ACL、无网络能力和最小环境变量。编译器与被评测程序使用相同的隔离工作区策略，禁止把编译阶段留在宿主机直接执行。

代码执行采用语言适配器配置，而不是在路由中写死命令。每种语言提供源文件名、编译命令、运行命令、工具链路径和可选能力；新增语言只需增加适配器及测试。危险代码扫描只用于提前给用户友好提示，不能替代沙箱。

## 用户、权限与数据一致性

引入集中式输入校验和账户服务：规范化用户名和邮箱、密码强度、重复注册、并发唯一键冲突、禁用账户、登录失败限速和会话安全统一处理。所有浏览器写操作使用 CSRF 保护；登出改为 POST。管理员操作不得禁用自己、降权自己或移除最后一个可用管理员；密码重置生成一次性临时密码并要求首次登录修改，不能写入日志或长期 flash 消息。公开 API 必须过滤未公开题目、限制分页参数，并保证队列提交失败时数据库状态可恢复。

## UI 与部署体验

前端改成传统 OJ 风格：白色内容区、浅灰背景、单一蓝色强调色、清晰表格、状态标签、统一错误提示和可读的移动端折叠布局。移除渐变、暗色切换和装饰性 emoji；样式集中到 `app/static/css/site.css`，模板只保留语义化类名。

Windows 部署器使用 Tkinter，提供“检查环境、创建虚拟环境、安装依赖、下载项目内 MinGW/JDK、生成 `.env`、初始化数据库、启动服务”流程。编译和运行始终使用项目内绝对路径；部署器设置内网监听地址、防止使用 Flask 开发模式作为生产入口，并支持备份 SQLite 数据库。

## 测试与验收

增加单元、集成、端到端和安全回归测试，覆盖权限边界、CSRF、账户异常、未公开数据、队列幂等、编译错误、超时、内存、超大输出和进程树清理。压力测试必须显式限制为短时、低并发、有限题目和有限 Worker，并在运行前检查配置上限；不执行无限循环或无限内存测试而不设置外部超时。验收要求：`compileall`、Ruff、完整 pytest、受控安全测试全部通过，并在 Windows 上完成一次部署向导的无交互冒烟验证。
