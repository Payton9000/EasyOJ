# EasyOJ 生产加固设计

## 目标

面向 Windows 内网教学场景，提高评测安全边界、队列可靠性、题面/比赛交互、部署可诊断性和测试数据管理的鲁棒性，同时保留未来扩展语言与题库的空间。

## 设计范围

- **评测资源**：为每个评测任务建立聚合内存、进程数、CPU/时间和磁盘约束；启动阶段先建立 Job Object，失败时立即终止并清理。
- **队列生命周期**：拒绝停止状态下的新任务；启动时恢复遗留任务；监测长期 Queued、失联 worker 和重评测入队失败。
- **测试数据**：上传前验证路径和配额，拒绝符号链接/Windows reparse point，限制单文件、单题、全局容量，并提供流式迭代接口。
- **账户与比赛**：比赛密码只保存哈希；提交使用服务端幂等键；比赛结束后只读展示并明确提供练习入口。
- **部署与可观测性**：增加严格 `/healthz`，部署 GUI 使用有界日志和精确健康检查；工具链下载固定来源并做 SHA-256 校验。
- **前端体验**：隔离用户草稿，降低 localStorage 写入频率，状态与错误可双语显示，结果标签支持完整键盘操作。
- **运营维护**：优化列表页计数查询；增加安全的 judge 日志/临时目录保留清理；将数据库初始化迁移收敛为一次性、可失败启动流程。

## 兼容性与取舍

保留现有数据库状态值和 API 字段，新增字段/配置提供默认值；旧比赛密码在成功登录后一次性升级为哈希。保留 `load_test_cases` 兼容调用，同时让评测主路径使用迭代器，避免一次性加载整题数据。未知或缺失的工具链校验值必须阻止部署，而不是放行未经校验的可执行文件。

## 验收标准

每个模块先有失败测试再实现；完成后运行针对性单元/集成测试、完整 pytest、Ruff、Windows safe verification，以及小规模有界并发 smoke。所有资源和清理测试必须有明确上限，不能执行无限 soak 或破坏性删除。
